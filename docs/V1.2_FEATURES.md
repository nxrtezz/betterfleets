## Requests System

### Overview
A comprehensive request system for users to submit improvements, bug reports, and feature requests for BetterFleets. The system supports multiple categories and includes tracking, comments, and status management.

### Features

#### Request Categories
- **Vehicle**: Requests related to specific vehicles (new vehicles, corrections, etc.)
- **Service**: Requests related to bus services and routes
- **Operator**: Requests related to operator information
- **Vehicle Type**: Requests for new vehicle types or corrections
- **Livery**: Requests for liveries and branding
- **Site Feature**: General feature requests for the BetterFleets platform
- **Named Page**: Requests for named vehicle pages
- **Other**: General requests that don't fit other categories

#### Request Status Workflow
1. **Open**: New request submitted
2. **In Progress**: Request is being worked on
3. **Resolved**: Request has been completed
4. **Closed**: Request closed without resolution
5. **Declined**: Request rejected

### User Interface

#### Creating Requests
- Navigate to `/requests/create/`
- Select category from dropdown
- Fill in title and description
- Category-specific fields appear based on selection:
  - Vehicle: Link to vehicle, fleet number, registration
  - Service: Link to service, route
  - Operator: Link to operator
  - Vehicle Type: Link to vehicle type
  - Livery: Link to livery
  - Site Feature: Expected behaviour description

#### Viewing Requests
- List view at `/requests/` with filtering by:
  - Category
  - Status
  - Author
  - Search terms
- Detail view shows:
  - Full request information
  - Timeline of all changes
  - Comments section
  - Status change controls (staff only)

### API Endpoints

#### Create Request
```
POST /requests/create/
```

#### List Requests
```
GET /requests/?category=<type>&status=<status>&search=<query>
```

#### Request Detail
```
GET /requests/<id>/
```

#### Add Comment
```
POST /requests/<id>/comment/
```

#### Change Status (Staff Only)
```
POST /requests/<id>/status/
```

### Database Models

#### Request
- `title`: Request title
- `description`: Detailed description
- `category`: Request category
- `status`: Current status
- `author`: User who created request
- `vehicle`, `service`, `operator`, `vehicle_type`, `livery`: Linked objects
- `fleet_number`, `registration`, `route`: Additional details
- `expected_behaviour`: For feature requests
- `resolved_by`, `resolved_at`: Resolution tracking
- `history`: Simple history tracking

#### RequestComment
- `request`: Related request
- `author`: Comment author
- `content`: Comment text
- `created_at`, `updated_at`: Timestamps

#### RequestHistory
- `request`: Related request
- `user`: User who made change
- `action`: Action type (created, updated, status_changed, commented)
- `description`: Action description
- `related_object_type`, `related_object_id`: Optional linked object

### Permissions
- All authenticated users can create requests
- Request authors can edit their own requests
- Staff users can change request status
- All authenticated users can comment on requests

## Profile Page Redesign

### Overview
The user profile page has been redesigned with a tabbed interface for better organization and user experience.

### Tabs

#### Actions Tab
- Displays a combined timeline of user activity:
  - Vehicle edits (revisions)
  - Vehicle reviews
  - Photo uploads

  - Liveries ridden
  - Vehicles ridden
  - Operators photographed (from photo logs)

  - Liveries photographed

  - Total edits
  - Total reviews

- Each livery shows:

- JavaScript for tab switching and AJAX loading
- Responsive design with mobile-friendly layout

#### AJAX Endpoint

### CSS Styling

## Statistics Tabs

### Overview
Statistics tabs have been added to Operators, Organisations, Government Authorities, and Manufacturers (Divisions) pages to provide fleet breakdowns and visual charts.

### Available Statistics

#### Operator Statistics
- Total vehicles count
- Vehicle type breakdown (bar chart with percentages)
- Livery breakdown (grid with color previews)
- Garage breakdown (if operator has 2+ garages)

#### Organisation Statistics
- Total vehicles across all operators
- Total operators count
- Vehicle type breakdown
- Livery breakdown

#### Government Authority Statistics
- Total vehicles across all operators
- Total operators count
- Vehicle type breakdown
- Livery breakdown

#### Manufacturer Statistics
- Total vehicles
- Total vehicle types
- Vehicle type breakdown
- Livery breakdown
- Operator breakdown (with links)

### Implementation

#### Statistics Module
- New file: `busstops/statistics.py`
- Functions for each entity type:
  - `get_operator_statistics(operator)`
  - `get_organisation_statistics(organisation)`
  - `get_government_authority_statistics(authority)`
  - `get_organisation_manufacturer_statistics(manufacturer)`

#### Templates
- `busstops/templates/operator_stats_tab.html`
- `busstops/templates/organisation_stats_tab.html`
- `busstops/templates/government_authority_stats_tab.html`
- `busstops/templates/manufacturer_stats_tab.html`

### Usage
Statistics can be included in any template by:
```python
from busstops.statistics import get_operator_statistics
stats = get_operator_statistics(operator)
```

Then render the appropriate stats tab template.

## Editing Withdrawn/Preserved Vehicles

### Overview
Vehicles can now be edited regardless of their withdrawn or preserved status. This allows for legitimate improvements to historical records.

### Changes Made

#### Vehicle Model (`vehicles/models.py`)
Modified `is_editable()` method:
- Removed restriction on preserved vehicles
- Removed restriction on withdrawn vehicles
- Only locked vehicles remain non-editable

**Before:**
```python
def is_editable(self) -> bool:
    if self.locked:
        return False
    if self.preserved:
        return False
    if self.withdrawn and (not self.latest_journey or ...):
        return False
    return True
```

**After:**
```python
def is_editable(self) -> bool:
    if self.locked:
        return False
    # Vehicles remain editable regardless of withdrawn or preserved status
    # This allows legitimate improvements to historical records
    return True
```

### Rationale
- Historical records often need corrections as new information becomes available
- Preserved vehicles may have details that need updating
- Withdrawn vehicles may have incorrect information that should be fixed
- Locking mechanism still protects truly immutable records

## Advanced Mode

### Overview
Advanced Mode provides power users with additional editing controls and the ability to store custom metadata on vehicles.

### Features

#### User Setting
- New field: `User.view_advanced` (Boolean)
- Users can enable/disable in profile settings
- Controls visibility of advanced editing controls throughout the site

#### Vehicle Advanced Field
- New field: `Vehicle.advanced` (JSONField)
- Stores arbitrary key-value pairs
- Examples of usage:
  - Historic ownership information
  - Internal notes
  - Custom metadata not fitting standard fields
  - Power user annotations

### Admin Interface

#### Vehicle Admin
- Advanced field added to fieldset (collapsed by default)
- Can be edited in Django admin
- JSON validation for valid data

#### User Admin
- View Advanced checkbox added to user form

### Form Changes
- `UserForm` includes `view_advanced` field
- Checkbox in profile settings to enable/disable

### Migration
- `accounts/migrations/0002_user_view_advanced.py`
- `vehicles/migrations/0097_vehicle_advanced.py`

### Usage Example
```python
vehicle.advanced = {
    "historic_owners": ["FirstBus", "Stagecoach"],
    "internal_notes": "Special variant with different seating",
    "custom_id": "BF-12345"
}
vehicle.save()
```

## Expanded Fleet List Filters

### Overview
The operator fleet list page now supports expanded filtering options for better navigation of large fleets.

### New Filters

#### Garage Filter
- Filter vehicles by garage assignment
- Dropdown shows all garages for the operator
- Only visible when operator has garages

#### Livery Filter
- Filter vehicles by livery
- Dropdown shows all liveries used by operator
- Color preview in dropdown (if available)

#### Vehicle Type Filter
- Filter vehicles by vehicle type
- Dropdown shows all vehicle types in operator's fleet

#### Logged Status Filter (Authenticated Users)
- Filter by ride/photo logging status:
  - Ridden: Vehicles user has ridden
  - Photographed: Vehicles user has photographed
  - Not Ridden: Vehicles user hasn't ridden
  - Not Photographed: Vehicles user hasn't photographed

### Implementation

#### View Changes (`vehicles/views.py`)
- Added filter logic in `operator_vehicles` view
- Context variables for selected filters
- Queryset filtering based on GET parameters

#### Template Changes (`vehicles/templates/operator_vehicles.html`)
- New filter form section
- Dropdowns for each filter type
- Apply and Clear buttons
- Responsive layout

### URL Parameters
```
?garage=<id>&livery=<id>&vehicle_type=<id>&logged=<status>
```

### Performance Considerations
- Filters applied before annotations for efficiency
- Uses existing indexes on foreign keys
- Logged status uses existing annotations

## Favourites System

### Overview
Users can favourite operators, vehicles, and services for quick access. Maximum 15 favourites per type per user.

### Features

#### Favourite Types
- **Operator**: Favourite bus operators
- **Vehicle**: Favourite specific vehicles
- **Service**: Favourite bus services/routes

#### Limits
- Maximum 15 favourites per type per user
- Enforced at model level with validation
- Clear error message when limit reached

#### Notes
- Optional notes field for each favourite
- Store personal reminders or information

### Database Models

#### Favourite
- `user`: User who favourited
- `favourite_type`: Type of favourite (operator/vehicle/service)
- `operator`, `vehicle`, `service`: Linked object (one set based on type)
- `created_at`: When favourited
- `notes`: Optional notes
- Unique constraint on (user, type, object)

### API Endpoints

#### Add Favourite
```
POST /favourites/add/
Parameters:
- type: "operator" | "vehicle" | "service"
- operator_id / vehicle_id / service_id: ID of object
- notes: (optional) notes string
```

#### Remove Favourite
```
POST /favourites/remove/<favourite_id>/
```

#### Toggle Favourite
```
POST /favourites/toggle/
Parameters:
- type: "operator" | "vehicle" | "service"
- operator_id / vehicle_id / service_id: ID of object
```

### AJAX Support
All endpoints support AJAX requests:
- Returns JSON response
- Includes success/error status
- Returns favourite ID and status

### Usage Example
```javascript
fetch('/favourites/toggle/', {
    method: 'POST',
    headers: {
        'X-Requested-With': 'XMLHttpRequest',
        'Content-Type': 'application/x-www-form-urlencoded',
    },
    body: new URLSearchParams({
        type: 'vehicle',
        vehicle_id: '12345'
    })
})
.then(response => response.json())
.then(data => {
    console.log(data.is_favourited);
});
```

## Service Logging

### Overview
Users can log which services they have ridden or photographed, with visual indicators on service/route pages.

### Features

#### Service Log Model
- Track ridden status per service
- Track photographed status per service
- Optional notes for each service
- Timestamps for tracking

#### Logging Options
- Mark service as ridden
- Mark service as photographed
- Add notes about service
- Toggle status on/off

### Database Models

#### ServiceLog
- `user`: User who logged
- `service`: Service being logged
- `ridden`: Boolean - has user ridden this service
- `photographed`: Boolean - has user photographed this service
- `created_at`, `updated_at`: Timestamps
- `notes`: Optional notes
- Unique constraint on (user, service)

### API Endpoints

#### Log Service
```
POST /service-logging/log/
Parameters:
- service_id: ID of service
- ridden: "true" | "false"
- photographed: "true" | "false"
- notes: (optional) notes string
```

#### Toggle Ridden Status
```
POST /service-logging/toggle-ridden/<service_id>/
```

#### Toggle Photographed Status
```
POST /service-logging/toggle-photographed/<service_id>/
```

### UI Integration
To add service logging indicators to route pages:

1. Check if user has logged the service:
```python
from service_logging.models import ServiceLog

if request.user.is_authenticated:
    service_log = ServiceLog.objects.filter(
        user=request.user,
        service=service
    ).first()
    has_ridden = service_log.ridden if service_log else False
    has_photographed = service_log.photographed if service_log else False
```

2. Add toggle buttons in template:
```html
{% if request.user.is_authenticated %}
<button onclick="toggleRidden({{ service.id }})">
    {% if has_ridden %}✓ Ridden{% else %}Mark as Ridden{% endif %}
</button>
<button onclick="togglePhotographed({{ service.id }})">
    {% if has_photographed %}✓ Photographed{% else %}Mark as Photographed{% endif %}
</button>
{% endif %}
```

3. Add JavaScript handlers:
```javascript
function toggleRidden(serviceId) {
    fetch(`/service-logging/toggle-ridden/${serviceId}/`, {
        method: 'POST',
        headers: {
            'X-CSRFToken': getCookie('csrftoken'),
        }
    })
    .then(response => response.json())
    .then(data => {
        location.reload();
    });
}
```

### AJAX Support
All endpoints support AJAX for seamless UI updates without page reloads.

## Performance Considerations

### Database Indexes
All new models include appropriate indexes:
- Requests: status, category, created_at
- Favourites: user+type, type+created_at
- Service Logs: user+service, service+ridden, service+photographed

### Query Optimization
- Statistics queries use `select_related` and `prefetch_related`
- Fleet filters applied before annotations
- Livery collection loaded via AJAX for performance

### Caching
Consider caching:
- Statistics calculations (with appropriate invalidation)
- Livery collection HTML
- User favourite counts
